// multi-tenant AI SaaS reference architecture

One request, three ways to answer.

OmniScale routes every request through an autonomous agent that decides, per call, whether the answer lives in your documents (rag), an uploaded image (cnn), or a direct model completion (chat) — then bills, queues, and observes the whole thing like a real product would have to.

What it actually does

6 core systems
Autonomous agent routerbackend/agent.py
Classifies each prompt into RAG, CNN, or chat before answering, and grounds RAG answers only in retrieved chunks — never lets the model improvise over missing context.
Dynamic LLM providerGroq ⇄ Gemini
Resolves Groq or Gemini at runtime from whichever API key is present — no code change to swap providers, no dead branches for the unused one.
RAG retrieval engineFAISS + sentence-transformers
Per-user vector namespaces persisted to disk, chunked with overlap, cosine-similarity search — survives worker restarts, not held only in memory.
Computer vision pipelinePyTorch · ResNet18
Transfer-learning classification plus a 512-d pooled feature vector, run off the request path entirely — image analysis is a polled background job, not a blocking call.
Metered billingStripe Checkout + webhooks
Signature-verified, idempotent webhook handling with a permanent audit log of every financial event — tier changes, renewals, and failures all reconcile automatically.
Tiered rate limitingRedis fixed-window
Limits scale with subscription tier and enforce atomically under concurrent load, so free-tier abuse can't starve paying tenants.

On payouts: Stripe auto-settles to your bank on your dashboard's own schedule. This project implements standard Checkout + webhook billing correctly rather than calling the Payouts API directly — that endpoint is for Connect marketplaces disbursing other people's funds, not a SaaS billing its own users.
